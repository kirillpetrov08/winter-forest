# Пошаговое руководство по сборке, подписи и публикации «Winter Forest» в Google Play и RuStore

Эта инструкция написана максимально подробно — шаг за шагом, чтобы опубликовать игру мог даже разработчик, выкладывающий своё первое Android-приложение.

> **Правило безопасности:** никогда не отправляйте файл ключа (`.jks`), его base64-копию, пароли или секреты CI в переписку, чаты или Git-репозиторий! Храните ключ и пароли в надёжном менеджере паролей с резервной копией на зашифрованном носителе: при потере upload-ключа обновить приложение без обращения в поддержку магазина будет затруднительно.

---

## Шаг 1. Получение ID рекламных блоков в РСЯ и вставка в готовый код

Код приложения уже полностью готов к работе с **Yandex Mobile Ads SDK (`8.6.0`)** и **не требует переписывания классов**.

1. Зарегистрируйтесь или войдите в кабинет [Рекламной сети Яндекса](https://partner.yandex.ru/).
2. Перейдите в **Реклама в приложениях → Приложения → Добавить приложение**, укажите имя пакета `com.ayaks.winterforest`.
3. Создайте два блока:
   - **Адаптивный баннер (Sticky Banner)** → скопируйте его ID (например, `R-M-1234567-1`).
   - **Вознаграждаемая реклама (Rewarded)** → скопируйте его ID (например, `R-M-1234567-2`).
4. В корне проекта создайте файл `local.properties` на основе `local.properties.example` (файл `local.properties` уже добавлен в `.gitignore`) и вставьте ID в эти два поля:

```properties
sdk.dir=/путь/к/вашему/Android/Sdk

# 1) Вставить ID баннера сюда:
yandex.banner.id=R-M-1234567-1

# 2) Вставить ID rewarded сюда:
yandex.rewarded.id=R-M-1234567-2

# Оставьте false для боевой сборки:
yandex.debug.demo=false
```

*(Альтернативно для CI GitHub Actions добавьте эти же два значения в `Settings → Secrets and variables → Actions` под именами `YANDEX_BANNER_AD_UNIT_ID` и `YANDEX_REWARDED_AD_UNIT_ID`, либо пропишите их в `app-winterforest/src/main/res/values/ads.xml` в полях `yandex_banner_ad_unit_id` и `yandex_rewarded_ad_unit_id`. Если оставить поля пустыми — реклама безопасно отключена, игра полностью работает).*

## Шаг 2. Размещение файла `app-ads.txt` и Политики конфиденциальности

1. В репозитории уже создан файл `docs/app-ads.txt` со строкой:
   ```text
   yandex.com, 110347355, DIRECT
   ```
   **Обязательно сверьте эту строку с разделом `app-ads.txt` в вашем личном кабинете РСЯ перед публикацией!**
2. Опубликуйте сайт разработчика (например, на вашем домене `https://ваш-домен.ru` или бесплатно через GitHub Pages репозитория `<ваш-логин>.github.io`), разместив:
   - в корне домена файл `/app-ads.txt` → должен открываться по прямой ссылке `https://<ваш-домен>/app-ads.txt`;
   - страницу с текстом `store/privacy-policy.md` → например `https://<ваш-домен>/privacy-policy`.
3. Проверьте в обычном окне браузера (в режиме инкогнито), что обе ссылки открываются по `HTTPS` с кодом `200 OK` без редиректов на страницы авторизации.

## Шаг 3. Создание ключа подписи релиза (`upload-keystore.jks`)

Придумайте надёжный случайный пароль длиной **не менее 12 символов** (заглавные и строчные буквы, цифры, спецсимволы) и сохраните его в менеджере паролей.

Выполните на своём компьютере (требуется установленный JDK 17 или JDK 21):

```bash
keytool -genkeypair \
  -v \
  -keystore upload-keystore.jks \
  -keyalg RSA \
  -keysize 4096 \
  -validity 10000 \
  -alias winterforest_upload
```

> **Единый ключ для RuStore и Google Play:** обязательно сохраните надёжную резервную копию этого ключа, чтобы подписывать одним и тем же ключом обновления для RuStore и (при включении Play App Signing) загружать сборки в Google Play Console.

### Подключение ключа для локальной сборки:
Скопируйте `keystore.properties.example` в `keystore.properties` в корне репозитория (**никогда не коммитьте `keystore.properties` и `*.jks` в Git — они уже добавлены в `.gitignore`!**):

```properties
storeFile=upload-keystore.jks
storePassword=ВАШ_ПАРОЛЬ_ОТ_12_СИМВОЛОВ
keyAlias=winterforest_upload
keyPassword=ВАШ_ПАРОЛЬ_ОТ_12_СИМВОЛОВ
```

### Подключение ключа и активация GitHub Actions CI:
> **Важно (ограничение прав GitHub App):** токен автоматической интеграции GitHub App не имеет права `workflows` для прямой записи в `.github/workflows/`, поэтому готовый workflow сохранён в репозитории по пути [`ci/android-ci.yml`](../ci/android-ci.yml). Чтобы включить автосборку на GitHub Actions, один раз перенесите его локально под своим аккаунтом владельца репозитория:
> ```bash
> mkdir -p .github/workflows && git mv ci/android-ci.yml .github/workflows/android-ci.yml && git commit -m "chore(ci): enable GitHub Actions Android workflow" && git push
> ```

Перекодируйте ключ в одну строку base64 на своём компьютере:
- Linux / macOS: `base64 -w 0 upload-keystore.jks` *(на macOS: `base64 -i upload-keystore.jks | tr -d '\n'`)*
- Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks"))`

Откройте репозиторий на GitHub → **Settings → Secrets and variables → Actions → New repository secret** и добавьте:
- `KEYSTORE_BASE64` — строка base64 файла `upload-keystore.jks`
- `KEYSTORE_PASSWORD` — пароль хранилища (≥ 12 символов)
- `KEY_ALIAS` — `winterforest_upload`
- `KEY_PASSWORD` — пароль ключа (≥ 12 символов)
- `YANDEX_BANNER_AD_UNIT_ID` — ID адаптивного баннера из кабинета РСЯ
- `YANDEX_REWARDED_AD_UNIT_ID` — ID rewarded-блока из кабинета РСЯ

## Шаг 4. Сборка и проверка релизных файлов APK и AAB

Выполните в терминале из корня проекта:

```bash
# 1. Прогон всех юнит-тестов
./gradlew test

# 2. Сборка отладочного APK (для проверки на своём телефоне/эмуляторе)
./gradlew assembleDebug

# 3. Сборка подписанного релизного APK (для загрузки в RuStore)
./gradlew assembleRelease

# 4. Сборка подписанного релизного Android App Bundle AAB (для Google Play и/или RuStore)
./gradlew bundleRelease
```

Готовые артефакты появятся по путям:
- Debug APK: `app-winterforest/build/outputs/apk/debug/app-debug.apk`
- Release APK: `app-winterforest/build/outputs/apk/release/app-release.apk`
- Release AAB: `app-winterforest/build/outputs/bundle/release/app-release.aab`

> **Не нажимайте на собственную боевую рекламу** при проверке релизной сборки на телефоне — это нарушает правила РСЯ и может привести к блокировке рекламного кабинета!

## Шаг 5. Публикация в Google Play Console

1. Откройте [Google Play Console](https://play.google.com/console/) → **Создать приложение**:
   - Название: `Winter Forest: Выживание 3D`
   - Язык по умолчанию: `Русский (ru-RU)`
   - Приложение или игра: **Игра**
   - Платно или бесплатно: **Бесплатно**
2. В разделе **Контент приложения (App content)** последовательно заполните:
   - **Политика конфиденциальности:** вставьте HTTPS-ссылку на опубликованный `privacy-policy`.
   - **Реклама (Ads):** выберите *«Да, в приложении есть реклама»*.
   - **Доступ к приложению:** *«Все функции доступны без ограничений»* (логин не требуется).
   - **Возрастные ограничения (Content ratings):** заполните анкету IARC для приключенческой игры про выживание в природе без крови и мультиплеера.
   - **Целевая аудитория:** выберите возрастные группы `13+` / `16+` / `18+` (не отмечайте младшую детскую категорию до 13 лет, если используете стандартную персонализированную рекламу с `AD_ID`).
   - **Безопасность данных (Data Safety):** заполните строго по инструкции `store/data-safety.md`.
   - **Финансовые / медицинские функции / государственные приложения:** везде **Нет**.
3. В разделе **Настройки магазина → Контактные данные магазина** обязательно укажите:
   - Email: `kirillpetrov08@gmail.com`
   - **Веб-сайт:** `https://<ваш-домен>` (тот самый домен, в корне которого лежит `/app-ads.txt`!).
4. В разделе **Основная страница магазина** загрузите материалы из папки `store/`:
   - Тексты из `store/store-listing-ru.md` (и при желании добавьте перевод `en-US` из `store/store-listing-en.md`);
   - Иконку `store/icon-512x512.png` (`512×512`);
   - Картинку для описания `store/feature-graphic-1024x500.png` (`1024×500`);
   - Скриншоты для телефона из `store/screenshots/01-main-menu.png` … `07-hunters-cabin.png`.
     > **Честная маркировка происхождения кадров:** подготовленные в репозитории файлы `store/screenshots/01-main-menu.png` … `07-hunters-cabin.png` являются **программными 3D-рендерами сцен и HUD** (созданными скриптом `scripts/generate_store_graphics.py` по формулам процедурного шума Перлина/Вороного, тумана, освещения и точной разметки Compose-экранов игры), а **не** прямыми снимками с физического Android-устройства. После установки APK на телефон вы можете дополнить или заменить их живыми снимками командой:
     > `adb exec-out screencap -p > store/screenshots/device-01.png`
5. Перейдите в **Тестирование / Рабочая версия (Production)** *(для новых личных аккаунтов разработчика Google Play сначала пройдите этап закрытого тестирования 14 дней с 12 тестировщиками, если аккаунт требует этого)* → загрузите файл **`app-winterforest/build/outputs/bundle/release/app-release.aab`** (`targetSdk = 36`, соответствует требованиям Google Play 2026 года) → укажите примечания к выпуску → отправьте на проверку!

## Шаг 6. Публикация в RuStore Консоли

1. Войдите через VK ID в [RuStore Консоль](https://console.rustore.ru/) и нажмите **Добавить приложение**.
2. Загрузите подписанный **`app-winterforest/build/outputs/apk/release/app-release.apk`** (или `app-release.aab`).
3. Заполните карточку приложения данными из `store/store-listing-ru.md`:
   - Название: `Winter Forest: Выживание 3D` (до 30 символов);
   - Краткое описание (до 80 символов) и полное описание (до 4000 символов);
   - Категория: **Игры → Приключения / Выживание**;
   - Иконка: `store/icon-512x512.png` (`512×512 PNG`, сплошной фон без прозрачных углов, < 3 МБ);
   - Скриншоты телефона: загрузите от 4 до 7 кадров `1080×1920 PNG` из `store/screenshots/` (каждый < 3 МБ, с читаемым русским интерфейсом без системной строки Android).
4. Укажите возрастное ограничение (`12+`), ссылку на **Политику конфиденциальности**, контактный email `kirillpetrov08@gmail.com` и **сайт разработчика** с `app-ads.txt`.
5. В разделе **Безопасность данных и монетизация** отметьте наличие рекламы и укажите рекламный SDK **Yandex Mobile Ads (РСЯ)** согласно `store/data-safety.md`.
6. Нажмите **Отправить на модерацию** и дождитесь публикации!
