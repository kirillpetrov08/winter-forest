# Технический аудит ассетов Winter Forest

**Дата:** 2026-10-25 · **Ветка:** `arena/155c7e9b-winter-forest` · **База:** `main@e2a2806`
**Объём:** 33 модели / 46 `mesh*.obj` (293 566 треугольников), 10 мировых текстур, 33 иконки, 24 глифа, 84 расстановки + 1 служебная в 5 районах, 42 исходных `.blend`.

## Как проводился аудит

| Что проверялось | Инструмент / метод |
|---|---|
| Габариты, min-Y, число треугольников, вырожденные фейсы | собственный разбор всех `mesh*.obj` по граням (не по списку `v`) |
| UV: схлопнутые, выходящие за [0,1], растянутые | площадь-взвешенный анализ треугольников в UV-пространстве |
| Нормали: инвертированные, дублированные двусторонние пары | сравнение геометрической нормали (по обходу) с записанной `vn` |
| Битые ссылки индексов | полный проход `f` против количества `v`/`vt`/`vn` |
| Пересечения пропов | OBB + SAT по повёрнутым габаритам, проникновение в метрах |
| Визуальная проверка модели | программный растеризатор `tools/preview_prop.py` |
| Источники `.blend` | `tools/blend2obj.py` (объекты сцены) |
| Память GPU/CPU | расчёт по размерам источников, `textureSize` качества и коду загрузки |

**Шкала критичности**
- **Critical** — краш, утечка/переполнение памяти или грубо сломанная картинка/локация.
- **Major** — заметный визуальный или игровой дефект, но играть можно.
- **Minor** — полировка, экономия, аккуратность.

### 1.4 Не-квадратные текстуры растягивались — Critical (исправлено)

`AssetTextureLibrary.loadRgbaFromAsset` масштабировал любую текстуру в квадрат `outSize × outSize`.
`models/barrel/diff.png` и `models/oak_a|b|c/diff.png` — **512×256**: изображение растягивалось вдвое по вертикали (искажение деталей), а при `textureSize=1024/2048` — ещё и апскейлилось.
**Исправлено:** новый `AssetTextureLibrary.loadModelTexture` грузит текстуру в нативном размере (только уменьшение через `inSampleSize`).

### 1.5 Апскейл текстур моделей и утечка видеопамяти — Critical (исправлено)

Тот же код грузил текстуры всех 33 моделей в разрешении `quality.textureSize`:

| Качество | `textureSize` | VRAM на текстуры пропов (до) | после |
|---|---|---|---|
| LOW | 256 | 8.6 МБ | 8.6 МБ |
| MEDIUM | 512 | 34.6 МБ | 34.6 МБ |
| **HIGH (по умолчанию)** | **1024** | **138 МБ** | **34.6 МБ** |
| **ULTRA** | **2048** | **554 МБ** | **34.6 МБ** |

Источники — 512², то есть на HIGH/ULTRA текстура раздувалась в 4–16 раз **без единого нового пикселя**. На ULTRA это гарантированный OOM на любом телефоне.
**Исправлено:** грузим нативно (512²/512×256), апскейла больше нет.

### 1.6 Иконки HUD декодировались в полном размере — Critical (исправлено)

`HudComponents.rememberAssetIcon` вызывал `BitmapFactory.decodeStream` без `inSampleSize`: каждая иконка 1024² = **4 МБ heap** (глифы 512² = 1 МБ). Десяток иконок на экране инвентаря — 40+ МБ и постоянные GC-паузы.
**Исправлено:** декод с `inSampleSize` под цель 192 px (≈0.26 МБ на иконку), для глифов — 0.06 МБ.

### 2.3 Схлопнутые UV `cabin_wood` — Critical

- `models/cabin_wood/mesh.obj`: 27 407 из 31 915 треугольников (65.1%, с учётом площади) имеют все три UV в одной точке `(0, 1)` → весь сруб сэмплит **один тексель** и рисуется плоской тёмной заливкой.

- Подтверждено растеризатором: `tools/preview_prop.py cabin_wood` даёт ~90% незакрашенной тёмной поверхности.
- Рекомендация: переэкспорт `models/Log cabin with Fireplace/cabin 0324.blend` с внятной UV-развёрткой (Blender Smart UV Project, 512 px/м). Альтернатива без участия 3D-художника — трипланарная проекция UV на рантайме для треугольников со схлопнутыми UV (алгоритм описан в разделе 6).

### 2.5 Инвертированные нормали — Major

Доля треугольников, у которых записанная `vn` направлена **против** геометрической нормали:

| Модель | Доля | Модель | Доля |
|---|---:|---|---:|
| `bush_thicket` | 24.3% | `oak_a` | 10.4% |
| `cabin_burned` | 22.6% | `oak_c` | 9.7% |
| `oak_b` | 22.4% | `bush_dry` | 8.5% |
| `bush_green` | 11.5% | `cabin_stone` | 6.1% |
| `cabin_wood` | 4.5% | `cabin_bark` | 4.1% |
| `woodstack` | 2.3% | | |

Причина — дублированные пары с обратным обходом (двусторонняя листва): `oak_b` — 1 096 пар, `bush_thicket` — 540, `cabin_burned` — 107. Back-face culling в проекте **выключен** (`GL_CULL_FACE` не включается нигде), поэтому дубли не отсекаются, а дают двойной овердроу и разное освещение двух сторон одной карточки → пятнистое тёмное затенение кустов и кроны.
Рекомендация: пересчитать `vn` по обходу грани (плоские нормали) для листвы и убрать дубликаты; либо включить culling для материалов с гарантированной замкнутой геометрией (камень, изба, металл), оставив листву двусторонней.

### 2.6 Битые ссылки индексов — ОК

Полный проход по 46 `mesh*.obj` (после удаления мёртвого `fence`): ссылок за пределы `v`/`vt`/`vn` **нет**. Ранее в работе всплывали расхождения — они были следствием моего собственного скрипта чистки, а не ассетов (см. раздел 7.4).

## 3. Риггинг и parenting

### 3.1 Скиннинга нет — принято как архитектура

В ассетах нет скелета и весов. Все существа собраны из отдельных мешей, которые анимируются кодом:

| Объект | Меши | Сборка |
|---|---|---|
| `deer_body` | `mesh_body` + `mesh_leg0`, `mesh_leg1` | `buildEntityParts()`, ноги 0–1, пара 2–3 **зеркалируется в коде** |
| `wolf_body` | `mesh_body` + `mesh_leg0..3` | 4 ноги, полноценный шаг |
| `rat_body` | один меш | ног нет → крыса «плывёт» без анимации лап |
| `gate` | `mesh_frame`, `mesh_left`, `mesh_right` | створки поворачиваются вокруг шарнира, 95° |
| инструмент в руке | `mesh.obj` (`wooden_axe`, `pickaxe`, `spear`) | `buildToolHandVbo()`: `gripShift` −0.55…+1.30, `scale` 0.28–0.52, `remapXZ` для топора |

### 3.2 Олень без двух ног — Major (исправлено)

`models/deer_body/mesh_leg2.obj` и `mesh_leg3.obj` — **пустые файлы (0 граней)**, у оленя физически 2 ноги из 4. Код компенсирует зеркалированием (`mirrorX`), но:

- **было:** при зеркалировании инвертировались только `nx`, а `ny`/`nz` оставались — нормаль отражённой ноги смотрела внутрь, дальние ноги оленя и волка освещались как чёрные;
- **стало:** позиция X отражается, `ny`/`nz` меняют знак, а обход вершин в каждом треугольнике меняется (1↔2), чтобы лицевая сторона сохранялась и при включённом culling.

Рекомендация художнику: дорисовать `mesh_leg2/3` (или собрать оленя как волка) и убрать зеркалирование.

### 3.3 Отсутствие иерархии — Minor

`parent`/`child`-связей нет вообще: положение каждой части задаётся константами в коде (`buildEntityParts`, `buildToolHandVbo`, `rebuildStaticWorldArchitecture`). Это устойчиво (нечему «отвалиться»), но любая правка модели требует правки кода. Для `gate` шарнир задан смещением в коде — при замене модели створки поедут.

### 4.2 Зимовье охотника — коллизия не совпадает с моделью — Major

- `WorldCollision.HUNTER_CABIN = (7.2, 8.8, hw 2.9, hd 3.8)` — **осеориентированный** бокс 5.8×7.6 м с вырезанным проёмом (1.24 м).
- Модель `cabin_*` стоит с поворотом **3.6 рад**; её реальный след 3.0×7.4 м повёрнут на 206°.
- AABB примерно совпадает с крайними точками модели, но **в углах остаются невидимые стены до ≈1.0 м** от сруба, а дверной проём вырезан в грани AABB, а не в настоящей стене модели.
- Рекомендация: поддержать повёрнутые прямоугольники в `WorldCollision.Rect` (перенос точки в локальную систему, разрешение конфликта, обратный перенос) и задать стены по модели.

### 4.3 Высота зимовья меньше роста персонажа — Critical

- Модель `cabin_wood`: H = 1.86 м, в мире масштаб **0.78** → высота **1.45 м**.
- Камера игрока: `camY = py + 1.72` (рост персонажа ≈1.8 м).
- Внутри сруба достроены интерьерные элементы: труба печи (игровой объект до +1.72 м), «тёплое свечение» (до +1.62 м), — они **выходят сквозь крышу** высотой 1.45 м.
- Если игрок входит в проём (ширина 1.24 м при радиусе тела 0.42 — проходит), камера оказывается **выше конька**: интерьер виден сверху, крыша режется ближней плоскостью.
- Рекомендация: масштаб модели 1.0 (H = 1.86 м) + пересчёт интерьера под новый след и обновление коллизии; либо блокировка входа и превращение сруба в декорацию (тогда интерьер не нужен).

## 7. Что уже исправлено в этой итерации

### 7.1 Парсер OBJ — главный источник тормозов старта

`ObjParser.parseToExpandedFloats` вызывал `line.split(Regex("\\s+"))` **внутри цикла по строкам** — то есть компилировал новый `Pattern` на каждой из 3 339 959 строк (72 МБ OBJ) — и складывал результат в `ArrayList<Float>` (боксинг ~10.8 млн значений).

Переписан на рукописный сканер: обход строк через `indexOf('\n')`, свой разбор float (быстрый путь «знак + цифры + точка + цифры», экзотика — в stdlib), растущий `FloatArray`-буфер без боксинга.

Эквивалентность проверена: трансляция новой логики прогнана по всем 46 `mesh*.obj` и дала **побитово тот же** поток вершин, что и прежний алгоритм (0 расхождений из 46 файлов). В `ObjParserTest` добавлены тесты на CRLF, табы, экспоненциальную запись, битые индексы и бенчмарк-гвард; плюс тест «быстрый парсер == эталонная Regex-реализация» на 40 сгенерированных мешах.

### 7.2 Вес моделей: 84 МБ → 46 МБ

`tools/pack_animals_cabin.py` писал полный буфер вершин сцены в каждый файл материала. Для избы это 13 030 вершин и 394 652 UV на файл:

| Файл | Трис | Было | Стало |
|---|---:|---:|---:|
| `cabin_bark/mesh.obj` | 518 | 7.86 МБ | **0.05 МБ** |
| `cabin_burned/mesh.obj` | 357 | 7.86 МБ | **0.03 МБ** |
| `cabin_shingle/mesh.obj` | 234 | 7.85 МБ | **0.02 МБ** |
| `cabin_stone/mesh.obj` | 924 | 7.89 МБ | **0.10 МБ** |
| `cabin_wood/mesh.obj` | 31 915 | 9.42 МБ | **3.45 МБ** |
| `fence/mesh.obj` | 5 663 | 0.70 МБ | удалён (мёртвый ассет) |

Новый инструмент `tools/strip_unused_obj_verts.py` удаляет `v/vt/vn`, не участвующие ни в одной грани, сохраняя исходный порядок строк (диффы минимальны) и **перечитывая записанный файл с диска** для сверки раскрытого потока вершин. Всего ассеты: **136 МБ → 97 МБ**.

### 7.3 Нормали зеркальных ног + обход вершин

См. 3.2: `mirrorX` теперь даёт корректную нормаль `(nx, −ny, −nz)` и меняет обход, чтобы геометрия оставалась лицевой при любом режиме culling.

### 7.4 Коллизии ящиков

`SUPPLY_CRATE` 0.78 → 0.55 (по полуширине модели 0.95 м), добавлена ветка `MILITARY_CRATE → 0.55` (раньше военный ящик вообще не имел коллизии).

### 7.5 Текстуры моделей и иконки

См. 1.4–1.6: нативная загрузка текстур пропов (без апскейла и без растягивания не-квадратных), `inSampleSize` для иконок HUD.
